# DSCODE 0.7.39

This release repairs DeepSeek provider startup in the published terminal bundle and retains the Harness 0.2.0-rc.2 upgrade, native reminders, Computer Use 0.3.3 and optional Atomic Mail integration from 0.7.38.

- **Working DeepSeek entries:** Harness 0.2 separates its shared adapter library from the API-key and Account plugins. The bundle now ships both native plugin entries and points them at its patched adapter, retaining DSCODE effort policies. Existing API-key and Account settings row IDs remain unchanged. This fixes the `invalid plugin` activation error and missing API-key provider seen in a fresh 0.7.38 installation.
- **Installed provider verification:** the release gate now boots the installed launcher's local doctor and rejects plugin activation failures. The real Harness probe checks that both `deepseek-official` and `deepseek-account` register and resolve model information before it adds its offline fixture adapter. Fixture agent success can no longer hide this missing provider.
- **Publication boundary:** 0.7.38 reached npm and Hub before the public installation check found this problem; its remaining workflow was cancelled. The existing version and tag are retained. Install 0.7.39 instead.

Update the launcher with `npm install -g @toddzheng024/dscode@latest`, then run `dscode update` for an existing Hub profile. The Desktop extension remains qualified separately for official Harness 0.2.0-rc.2 on macOS Apple Silicon.

Verification passed `npm run check`: lint, both TypeScript checks, 1,091 unit/component tests, native integration, package checks and 63 offline evaluations; measured first-party `.mjs` coverage was 80.35%. The exact candidate also passed `verify:hub` in a clean temporary workspace: native locked installation, installed local diagnostics, both DeepSeek provider registrations and model resolution, ACP, agent execution, session messaging, cards, memory, failed-upgrade preservation and successful upgrade/rollback. Running that verification directly from the developer checkout was blocked by its local `.env` bootstrap setting; no local credentials were copied to the clean workspace. Documentation and tag-version checks passed before tagging. Real provider inference, live OAuth login, interactive desktop actions and real mail delivery have no automated case. Computer Use retains the upstream saved-skill restoration limitation documented in [0.7.38](0.7.38.md).
