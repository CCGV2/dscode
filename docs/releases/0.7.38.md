# DSCODE 0.7.38

Status: superseded by 0.7.39. This version reached npm and Hub, but a fresh public install exposed a broken DeepSeek provider entry point and the remaining release workflow was cancelled. Use 0.7.39 or later.

This release upgrades the terminal to Harness 0.2.0-rc.2, restores native reminder integration, and documents optional Atomic Mail MCP support.

The 0.7.37 candidate was cancelled before npm or Hub publication when its Node 22.19.0 coverage check failed. This version retains the upgrade and removes a stale source-map reference from the in-memory Ink test fixture. The failure was reproduced locally on Node 22.19.0; all 1,091 unit/component tests and coverage checks passed on that exact runtime after the fix. The original tag remains unchanged.

- **Aligned runtime:** the terminal and vendored TUI now use Harness `0.2.0-rc.2`, matching the existing Desktop target. All installed Harness packages have exact override pins, including the newly introduced shared account service. Existing DSCODE runtime patches retain their exact-version guards. The DeepSeek compaction evaluator uses the new header-based authentication interface; this release does not move to the `0.2.1` alpha channel.
- **Native reminders:** the terminal mounts the session controller and its host dependencies so the scheduler can deliver to live sessions and resume persisted sessions while the Host runs. `/schedule` reads the current reminder catalog instead of historical session events, refreshes while open, displays daily, weekly and cron rules, and surfaces read failures. The optional loopback login server also carries authenticated native Connection routes; no browser frontend is mounted. The host services also work with that listener disabled.
- **Computer Use compatibility:** update to `0.3.3`, whose declared compatibility includes the new Harness, and remove the retired Settings shim so the provider handles native configuration updates. The upstream saved-skill restoration limitation remains: after resuming a session, reload the Computer Use skill if its execution tools are absent. The activation tool remains available.
- **Optional Atomic Mail:** the [email guide](../email.md) and disabled example MCP row show how to opt in. Unconfigured or disabled rows start no Atomic Mail process and add no tools or server instructions to model context. Disabling or removing a configured row removes its current tools and instructions; it does not erase previous conversation history. This is a separate MCP integration and does not replace the existing email tools.
- **Reliable verification:** isolated test runtimes now carry the app-boot, Goal and subagent provider packages they exercise. Ink patch tests work in memory and OpenRouter timeout tests use a controlled clock. Fresh installs no longer depend on a previously patched developer tree. Installed-bundle probes include native live and cold-session reminder delivery.

Update with `npm install -g @toddzheng024/dscode@latest`, then run `dscode update` for an existing Hub profile. Fresh installs provision their matching profile on first launch. The Desktop extension remains qualified separately for official Harness 0.2.0-rc.2 on macOS Apple Silicon; its exact release archive is revalidated by the release workflow.

Verification of this change passed a clean `npm ci --ignore-scripts` and `npm run check`: lint, both TypeScript checks, 1,091 unit/component tests, native integration and package checks, and 63 offline evaluation tests. Measured first-party `.mjs` line coverage was 80.37%; the TypeScript terminal is outside that metric. Real Chrome checks passed. The macOS doctor passed preset activation, worktrees, shell persistence, approvals, compaction and session resume; an isolated run with `DSCODE_ACCOUNT_LOGIN=0` also passed live and cold-session reminder delivery. Computer Use helper 0.3.3 passed initialization and its health handshake. Linux arm64 on Node 22.23.3 passed all seven end-to-end stages, including installed bundle execution, failed-upgrade preservation and successful upgrade/rollback. Documentation, lint and tag-version checks are repeated for the version bump, and CI requalifies the exact versioned terminal and Desktop archives before publication.

Real provider inference, live OAuth login, interactive desktop actions and real mail delivery have no automated case in this release. Fixture success establishes runtime and transport behavior, not model quality or those external account flows.
